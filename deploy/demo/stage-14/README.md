# Integration Demo Stage 14 runtime contract

Stage 14 extends the localhost-only synthetic demonstration to Governed Git Source Commit. It binds the exact approving Human Review, accepted Tests, authoritative inert Code Generation candidate, and `HumanReview`-stopped delivery run to signed action-specific OPA scope, exact change-set validation, a provider-neutral `IInstitutionalGitGateway`, result authorization, and immutable PostgreSQL evidence.

Deployment operations must provision all Stage 13 inputs outside Git plus `.runtime/integration-demo-stage-14/git/seed.sql`, containing the exact `HumanReview`-stopped run snapshot. They must configure `Platform:SoftwareFactory:GitRuntime` with a real institutionally approved HTTPS Git gateway, gateway/operator identities, positive request/response bounds, signature algorithm, and pinned public verification trust. The gateway must independently verify repository `repository://demo/permit-renewal-service`, clean base `aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`, change branch `changes/demo-permit-renewal-stage-14`, signing policy `policy://demo/git-signing/v1`, and the exact reviewed change set. No repository credential, signing key, private key, endpoint, trust material, institutional data, commit, or successful result is stored in Git.

The policy permits only `internal-service.git.commit`, the two reviewed normalized candidate paths, exact immutable digests, controlled commit metadata, a non-protected branch, and `git-commit-result`. OPA authorizes before repository read, candidate disclosure to the gateway, or source mutation. The gateway response must prove a clean exact base, one signed immutable commit, exact applied changes, no protected-branch mutation, no force update or history rewrite, no pull request, no CI/CD trigger, no artifact publication, and no production effect.

Repository defaults remain empty and fail closed. The demo must never substitute a fake repository, base, materializer, policy validation, commit, signature, gateway response, or successful result. Missing or mismatched prerequisite evidence, unauthorized path, secret detection, dirty/stale base, unsigned response, invalid trust, or unavailable dependency fails closed. The receipt records `SourceMutationOccurred: true`, `ProductionEffectOccurred: false`, `CiCdTriggered: false`, and `CanAdvance: false`; it cannot create a PR, trigger CI/CD, reach Production, or grant workflow authority.
