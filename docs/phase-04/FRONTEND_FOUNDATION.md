# Phase 04 — Frontend Foundation

Status: **Implemented**  
Depends on: **Phase 03 — Backend Foundation**

## Implemented foundation

- Blazor WebAssembly remains the approved frontend runtime.
- A responsive, accessible platform shell replaces the default template experience.
- The approved `BUILD <-> UNDERSTAND <-> OPERATE <-> ACT` model is represented as navigation and orientation only.
- Evidence is represented as a cross-cutting trust destination and remains unavailable until its approved phase.
- A scoped `ExperienceContext` establishes the presentation boundary without claiming identity or authorization.
- Keyboard focus visibility, semantic landmarks, responsive layouts, reduced-motion handling, loading state, and recoverable error messaging are established.

## Guardrails

- Navigation visibility does not grant access.
- No identity, RBAC, ABAC, policy enforcement, API contract, dashboard, or business capability is implemented in this phase.
- Future capability links are visibly unavailable rather than simulated.
- Server-side authorization remains mandatory when later capabilities are introduced.

## Deferred

- Identity and access enforcement: Phase 05.
- OpenAPI client contract: Phase 06.
- Domain and operational experiences: their respective roadmap phases.
- Intent-based Front Door: Phase 25.
